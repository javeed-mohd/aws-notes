Redirections (>):
=================

ls -l > output.txt
cat output.txt --> These both will execute as it is success

If command is success, redirect the output in output.txt

1 --> Success (ex: ls -l > output.txt) --> It stores the output of success
2 --> Failure (ex: lsasd(anything) -l 2> output.txt) --> It stores the output of failure
& --> success and failure

&> is for everything whether the code is success or failure to redirect the output to logs file (ex: ls -l &> output.txt) (ex: lsasd(anything) -l &> output.txt)
&>> is used for appending and prevent from overriding (ex: ls -l &>> output.txt) or (ex: lsasd(anything) -l &>> output.txt)

==================

Foreground
Red    --> 31

Yellow --> 33
Blue   --> 34
No Color --> 0 ("\e[0m")

Error Handling:
===============

set -e # This will be checking for errors, if errors it will Exit [ The purpose of VALIDATE() is that it checks for process and pints the log file.]

trap 'command(s)_to_run' ERR ( We will know where the error line is)

ex: trap 'echo "There is an error in $LINENO, Command: $BASH_COMMAND"' ERR

[We can use trap or validate in our poject as per requirement...... VALIDATE shows output on the terminal and we will know what is happening (Flow of the program) but TRAP doesn't show on the terminal, it shows only error. It can be used for code shortening. Both give the same result.]
