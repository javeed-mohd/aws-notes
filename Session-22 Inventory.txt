Playbook:
=========
--> An Ansible Playbook is a YAML-formatted file that is used for automation, defining tasks to configure, deploy, or manage instances. It acts as a "recipe" or "to-do list" that tells Ansible what actions to execute on specific target hosts, allowing for repeatable, scalable, and consistent automation. 


Inventory:
==========
--> What are the servers that ansible can connect to is called inventory

An Ansible inventory is a file (or script) that defines the managed nodes—servers, virtual machines, or network devices—that Ansible controls, typically organized into groups with specific variables. It acts as an "address book" or registry, enabling users to target specific environments.

Ansible is in python

We give inputs in playbook, ansible runs inside python connect to the systems using API

ansible frontend -i inventory.ini --list-hosts 	--> Listing all the hosts under frontend group in inventory.ini file

ansible all -i inventory.ini --list-hosts 	--> Listing all the hosts which are unique in the inventory.ini file

ansible roboshop -i inventory.ini --list-hosts  --> Listing all the hosts in roboshop project in inventory.ini file

ansible ungrouped -i inventory.ini --list-hosts --> Listing all the hosts in inventory.ini file which are not in a group
