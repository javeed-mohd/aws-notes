Idempotency:
============

Ansible is idempotent.

If we run script any number of times, it should give same results. This is called as idempotent.
(or)
Scripts should give same results even if you run them infinite times, This is called idempotency.

But, if we use command module then ansible won't be idempotent.

If we use collections then only ansible will be idempotent.

If Collections are available then use it and become idempotent, otherwise use command module or shell module and should handle the idempotency.....

It is used in Ansible, the automation and configuration management tool.

1. ansible-playbook
This is the command-line tool used to run Ansible playbooks.

A playbook is a YAML file that contains tasks to configure servers, install software, deploy applications, etc.

2. -i inventory.ini
-i stands for inventory.

The inventory file (inventory.ini in this case) defines the list of hosts (servers) where the playbook will run.

Example of an inventory.ini file:

[webservers]
web1.example.com
web2.example.com

[dbservers]
db1.example.com
Here, [webservers] and [dbservers] are groups, and the playbook can target specific groups or hosts.

ansible-playbook -i inventory.ini specifies which hosts to run the playbook on.
