Ansible Roles:
==============
Ansible role is proper directory structure of creating, managing and reusing playbooks. We can breakdown playbooks into multiple components like tasks, handlers, vars, meta, templates, files, etc. by default ansible loads main.yaml in these directories.

Catalogue depends on common folder is defined by META directory, so that we can use whatever required for our component(catalogue, cart, user, shipping, payment) file.

In common folder, we keep:
-> nodejs_setup -> enable, install nodejs, install dependencies
-> app_setup -> create directory, create system user, download code, unarchive code
-> system_setup

In META/main.yaml file we can mention dependencies.

1. Load catalogue role
2. Ansible finds META directory and main.yaml
3. It depends on common role
4. Ansible executes main.yaml in common/tasks folder
5. Now ansible starts executing catalogue/tasks/main.yaml
6. We extracted common code into common/app-setup.yaml
7. Ansible imports this into catalogue/tasks/main

failed_when: If you want to fail the task, ansible exit
changed_when: If rc=0, ansible considers as changed


ANSIBLE ROLES:
==============

roles/
    common/               # this hierarchy represents a "role"
        tasks/            #
            main.yml      #  <-- tasks file can include smaller files if warranted
        handlers/         #
            main.yml      #  <-- handlers file
        templates/        #  <-- files for use with the template resource
            ntp.conf.j2   #  <------- templates end in .j2
        files/            #
            bar.txt       #  <-- files for use with the copy resource
            foo.sh        #  <-- script files for use with the script resource
        vars/             #
            main.yml      #  <-- variables associated with this role
        defaults/         #
            main.yml      #  <-- default lower priority variables for this role
        meta/             #
            main.yml      #  <-- role dependencies
        library/          # roles can also include custom modules
        module_utils/     # roles can also include custom module_utils
        lookup_plugins/   # or other types of plugins, like lookup in this case


ANSIBLE-ROBOSHOP-ROLES FLOW EXECUTION PROCESS:
==============================================

If not given main.yaml in the folder then we need to call it explicitly....(only if given main.yaml in tasks, then it will be executed otherwise it won't).

=====> ansible-playbook -e component="{{ component }}" roboshop.yaml (No need of inventory.ini, user, password as we already provided in group_vars and inventory.ini files) 

=====> ansible-playbook -vv -e component="{{ component }}" roboshop.yaml (Debug mode, it gives huge logs and gives everything what happens in the background of ansible[If wanted in more detail then use -vvv]).

======> MULTIPLE CREATION: ansible-playbook -e component=catalogue roboshop.yaml ; ansible-playbook -e component=redis roboshop.yaml ; ansible-playbook -e component=user roboshop.yaml ; ansible-playbook -e component=cart roboshop.yaml ; ansible-playbook -e component=mysql roboshop.yaml


==> We can also give separate component values file in group_vars or else we can provide them in inventory.ini as well.

==> Template has placeholders so we used .j2 extension here to define catalogue.service as template and Files do not have placeholders. (But .j2 extension is not mandatory)

handlers
=========

Handlers are notifiers, you can call task-b when task-a changes. for example when a configuration changes you can restart the application using handlers. (It is required to restart the servers because whenever we run the application(instance) we get new user, download the application, unzipping and so on. So, it is mandatory to restart the application after every new addition). (If we change then only it restarts the application or else by default it will be as usual when it was first executed).

tags
=====

If you want a specific tag to run inside playbook, tag it and call it. When we start the component many tasks will be executed which are present inside the playbook, so we use TAGS to run only few or particular tasks whichever are required to be executed.

==>  ansible-playbook -e component=catalogue -t deployment roboshop.yaml  --> Run only which are with tags deployment on it.

==> ansible-playbook -e component=catalogue -t deployment roboshop.yaml -vvv

It will show the exact file and line number causing the issue.

You can keep all the components in one component file which is dependent on other files (Here Frontend). From there, it starts executing one by one as provided.

==> nohup ansible-playbook -e component="{ component }" roboshop.yaml &>/var/log/ansible.log & 	==> Use this format

==> tail -f nohup.out

==> less /var/log/ansible.log
