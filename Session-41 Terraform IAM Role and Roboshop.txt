ROUND ROBIN:
============

Round Robin in Load Balancing is a method used to distribute incoming network or application requests evenly across multiple servers in sequence.

In Round Robin, the load balancer sends each new request to the next server in order, then cycles back to the first server after reaching the last one.

Example with 3 servers:
-> Server 1
-> Server 2
-> Server 3

Request distribution:

Request		Server
=======		=======
Request 1	Server 1
Request 2	Server 2
Request 3	Server 3
Request 4	Server 1
Request 5	Server 2
Request 6	Server 3

So the order is:
S1 → S2 → S3 → S1 → S2 → S3 → ...

Architecture

Client → Load Balancer → Multiple Servers

The load balancer decides which server handles each request.

Advantages:
===========

==> Simple to implement
==> Equal distribution of traffic
==> No complex calculations
==> Works well when servers have similar capacity

Disadvantages:
==============

==> Does not consider server load or capacity
==> If one server is slower, it still receives the same number of requests
==> Not ideal for heterogeneous servers

Types:
~~~~~~
1. Weighted Round Robin ==> Servers with more capacity receive more requests.

2. Dynamic Round Robin ==> Distribution adjusts based on current server load.


Round Robin load balancing is used in:
-> Web servers
-> Cloud infrastructure
-> Reverse proxies like NGINX
-> DNS-based load balancing
