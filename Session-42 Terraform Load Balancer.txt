2 Ways to do it:

1. Rolling update: Update few instances at one time and other few after that so that we can get rid off the application downtime for somehow.
==================

A Rolling Update in Terraform means updating infrastructure gradually (one instance at a time or in batches) instead of replacing everything at once, so your service stays available with minimal downtime.

Terraform itself does not have a direct “rolling update” command. Instead, it works with the capabilities of the platform you’re using (AWS, Kubernetes, etc.) to perform rolling updates.

In a rolling update:
-> New instance/version is created.
-> Traffic is shifted to the new instance.
-> Old instance is terminated.
-> Process repeats until all instances are updated.

4 instances -> v4
4 instances -> v4
2 instances -> v4

We also call it as "ZERO DOWNTIME STRATEGY".


2.Other way (Immutable Infrastructure Deployment):
==================================================

-> Create new instance
-> Download v4 and configure it
-> Stop the instance
-> Take AMI

I can use this AMI to create instances
4 instances -> v4 (new)
4 instances -> terminate (old)
