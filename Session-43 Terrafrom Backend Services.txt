Launch Template(LT):
====================

A Launch Template in Terraform is used to define the configuration for launching EC2 instances in Amazon Web Services.
It stores settings like AMI, instance type, security groups, key pair, and user data, so you can reuse them when launching instances or Auto Scaling groups.

It acts as a reusable blueprint that stores instance settings such as:
-> AMI ID
-> Instance type
-> Security groups
-> Key pair
-> User data (startup scripts)
-> Network settings
-> Tags

This template can be reused when launching EC2 instances or creating Auto Scaling Groups, making infrastructure management easier and more consistent in Terraform.


Auto Scaling Group(ASG): 
========================

Auto Scaling in Terraform means automatically increasing or decreasing the number of EC2 instances based on load in Amazon Web Services.

It helps your application:
-> Handle high traffic automatically
-> Reduce cost when traffic is low
-> Maintain high availability

Auto Scaling = Automatic server adjustment

Example:
~~~~~~~~
-> If traffic increases → add more EC2 instances
-> If traffic decreases → remove extra instances

Health check grace period in autoscaling group ==> This time period delays the first health check until your instances finish initializing. It doesn't prevent an instance from terminating when placed into a non-running state.

Health check grace period is around 2 minutes -> 120 seconds. Usually, instance creation takes around 60 seconds so we keep health grace period as 120 seconds.


Auto Scaling Policy(ASP):
=========================

A Scaling Policy in Terraform defines when and how an Auto Scaling Group should increase or decrease EC2 instances in Amazon Web Services.

It tells the Auto Scaling Group what action to take when a condition (like high CPU usage) occurs.

Scaling Policy = Rule for scaling

Example:
~~~~~~~~
-> If CPU > 70% → add 1 instance
-> If CPU < 30% → remove 1 instance


1a instance (One data center -> Within this availability zone we can have 'n' number of requests which is free of cost but if we want to communicate with the other availability zone(1b) then aws will incur the data charges for that)
1b instance (Another data center -> Within this availability zone we can have 'n' number of requests which costs nothing but if we want to communicate with the other availability zone(1a) then aws will incur the data charges for that).

But, if we keep both the availability zones then we can have high availability of usage when one az gets downtime then other acts as a backup.

If launches fail in one Availability Zone, Auto Scaling will attempt to launch in another healthy Availability Zone.

Minimum	-> At any point of time, how many instances you want.
Desired -> How many you want right now.
Maximum	-> Maximum instances autoscaling group can create.

Minimum = 2
Desired = 4
Maximum = 10

In an Amazon EC2 Auto Scaling Auto Scaling Group (ASG), the parameters Desired, Minimum, and Maximum capacity control how many EC2 instances run automatically.


Minimum Capacity:
=================

The minimum number of instances that must always be running.

Auto Scaling will never scale below this number, even during low demand.

Ex:
Minimum = 2 → At least 2 EC2 instances will always run.


Desired Capacity:
=================

The number of instances the Auto Scaling group tries to maintain.

If instances fail (or) are terminated, the ASG will launch new ones to maintain this number.

Ex:
Desired = 4 → ASG ensures 4 instances are running.


Maximum Capacity:
=================

The upper limit of instances the Auto Scaling group can scale up to.

Even during high demand, it cannot exceed this number.

Ex:
Maximum = 10 → ASG can scale up to 10 instances only.

Example Configuration:

Setting	Value	Meaning
=============	=======
Minimum	2	Always keep at least 2 instances
Desired	4	Maintain 4 instances normally
Maximum	10	Scale up to 10 during high load

==> How Scaling Works

If CPU usage increases, scaling policies may increase instances from 4 → 6 → 8 → up to 10.

If traffic decreases, ASG reduces instances but never below 2.

Minimum → Lowest limit
Desired → Normal running number
Maximum → Highest limit
