Virtualization is the process of creating virtual (software-based) versions of physical resources like servers, storage, or networks.

==> One physical machine can run multiple virtual machines (VMs), each acting like a separate computer.

How it works:
=============

A special software called a hypervisor manages virtualization.

Examples:

VMware
VirtualBox

Microservices:
==============

-> App is split into small independent services
-> Each service can be deployed separately

Microservices architecture means building an application as a collection of small, independent services, where each service handles a specific function.

Instead of one big app (monolithic), you split it into multiple mini-apps that:

-> Run independently
-> Communicate via APIs

Characteristics:
================

-> Independent services
-> Each service has its own database
-> Communication via REST APIs / messaging
-> Can be deployed separately

Advantages:
===========

-> Easy to scale specific services
-> Faster deployments (update one service only)
-> Technology flexibility
-> Better fault isolation (one service fails, others continue)

Disadvantages:
==============

-> Complex to manage
-> Requires specific skills
-> Network latency between services
-> Harder debugging and monitoring

===========

-> Multiple programming languages
-> Release process is different

Containerization:
=================

Containerization is a technology that allows you to package an application along with all its dependencies (libraries, configs, runtime) into a single unit called a container.

==> Build once, run anywhere.

Your app will run the same way on any system because everything it needs is inside the container.

Containers share the host OS but stay isolated from each other.

Popular tools:

--> Docker
--> Kubernetes (for managing many containers)

1. No resource allocation, can use dynamically
2. Less cost
3. Less boot time
4. Less size
5. Portable and immutable
6. Scalable and reliable
7. Less privacy, but we can address this


Virtualization					Containerization
==============					================

Docker:
=======

Docker is a tool used for containerisation, which lets you package and run applications in containers.

Docker allows you to:

-> Build an app once
-> Run it anywhere (your laptop, server, cloud)

What is a container?

A container is:

-> Lightweight
-> Includes app + dependencies
-> Runs consistently across environments

Key components of Docker:
=========================

1. Docker Image

==> Blueprint of your application
==> Contains code + libraries

2. Docker Container

==>Running instance of an image

3. Dockerfile

==> Script with instructions to build an image

4. Docker Hub

==> Online repository to store images

Example workflow:
=================

Write your app
Create a Dockerfile
Build image
Run container

--> Your app works the same everywhere

Advantages:
===========

--> Fast and lightweight
--> Consistent environments
--> Easy deployment
--> Great for microservices

Disadvantages:
==============

-> Needs learning (Docker commands, concepts)
-> Security must be managed properly
-> Not ideal for all workloads

Docker = Tool that packages application + dependencies into lightweight containers for fast, consistent deployment.

-> Docker uses containerization, not virtualization
-> Containers share host OS kernel
-> Image is blueprint, container is runtime
-> Faster than VMs because no full OS boot
-> Used in microservices architecture

AMI = OS + System packages + App run time + App code + App dependencies -> Instance/Server/VM -> AMI ID
Docker Image = Bare minimum OS + System packages + App run time + App code + App dependencies -> Container (Running version of image)
