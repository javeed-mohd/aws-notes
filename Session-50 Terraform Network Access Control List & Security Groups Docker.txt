NACL (Network Access Control List) vs SG (Security Groups/Firewall):
====================================================================

SG -> Attached to instance
   -> Source can be IP address or other SG ID
   -> We can't add DENY rule
   -> Rules are stateful. If we are allowing port number 8080 from 10.0.1.34 (public/private/database subnet), while sending response back to the source an ephemeral port is opened. Since SG is stateful, we no need to write separate outbound rule.
   
NACL  -> Attached to subnet level
      -> Source can be subnet ID/ any cidr
      -> NACL is first layer of defence, then SG is next layer of defence
      -> You can add DENY rule.
      -> NACL are STATELESS. You have to write outbound rules also.

We have to change in both inbound & outbound rules then only traffic will come and response can be available.

Since NACLs are stateless, we must explicitly allow both inbound database traffic on port 27017 and outbound ephemeral ports (32768–65535) for return traffic, typically using subnet CIDR ranges to support autoscaling.

****BEFORE NACL creation,

==> When we create our own NACL, all traffic by default will be DENIED...So, we need to explicitly allow inbound & outbound rules to get the response as per the request.

FROM
=====

FROM is used to mention the base OS of the image. It should be the first instruction in Dockerfile.

build the image
===============

docker build -t from:1.0.0 .

-t ==> tag
1.0.0 ==> version
. ==> Current folder/directory

docker login -u username

docker push from:1.0.0

url/username/image-name:version
