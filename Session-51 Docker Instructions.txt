******
CMD
====

Used to run the container. It will be executed at the time of running the container. It will not execute at the time of building as that of run command.

We can have multiple RUN instructions inside dockerfile. But only one CMD instruction.

["executable","param1","param2"] ==> ["nginx","-g","daemon off;"]

systemctl start nginx -> It won't work inside images, systemctl is kernel level process.

Your command inside dockerfile should run in foreground, but you can take it into background.

LABEL
=====
adds the metadata to the image, and also used for filteration. Label is key-value pair. For multiple labels use \.

ex:- 
FROM almalinux:9
LABEL COURSE="Docker" \
      DURATION="12 Hours" \
      SOURCE="Amazon Web Services"

When large number of images are present in container then we can filter a particular image using ==> docker images --filter "label=COURSE=Docker"

docker images --help ==> Will get all the commands related to images

ENTRYPOINT
===========
ENTRYPOINT is used to provide the command executed by the container when it is started.

ping google.com ping facebook.com

******
CMD vs ENTRYPOINT
==================

We can override the command inside CMD instruction at run time... We can't override ENTRYPOINT command, if you try to do so it will go and append.. 
==> For best results we can always use both CMD and ENTRYPOINT

CMD can be used to provide the default args/inputs to ENTRYPOINT. 
If we want our own args, we can always override CMD at runtime.

==> NEVER RUN CONTAINERS WITH THE ROOT ACCESS...

******
ENV vs ARG
==========
ENV -> provide variables to container
ARG -> provide variables to image

==> ARG variables can't be accessed inside container, they are accessible only at the of image building. 

==> ENV variables can be accessed in container.

==> ARG can be first instruction in a special case to supply the version to base image.

docker build -t --build-arg username=what_user . ==> docker build -t --build-arg version=9 . 

==> ARG instruction of version can't be used beyond FROM instruction. It is allowed until FROM and then it won't apply anything from the very next line of FROM instruction...

USER:
======

The USER instruction sets the user name (or UID) and optionally the user group (or GID) to use as the default user and group for the remainder of the current stage.

Note: When the user doesn't have a primary group then the image (or the next instructions) will be run with the root group.

WORKDIR:
========

The WORKDIR instruction sets the working directory for any RUN, CMD, ENTRYPOINT, COPY and ADD instructions that follow it in the Dockerfile. If the WORKDIR doesn't exist, it will be created even if it's not used in any subsequent Dockerfile instruction.
