FROM -> refer base OS
RUN -> to configure image
CMD -> command executed at the time of container creation
LABEL -> metadata of the image
EXPOSE -> port information
ADD -> same as COPY but 2 extra capabilities. can download content directly from internet and untar the file.
COPY -> copy the files from local to image
USER -> to mention the user that container should be running on
WORKDIR -> working directory of the image/container
ENV -> env variables to the container
ARG -> variables to the image at build time, can't be accessed inside container. ARG can be first instruction before 	FROM to supply the version
ENTRYPOINT -> command to be executed while creating container. it can't be overridden, if we try it will go append. CMD can be overridden. CMD can supply default args for ENTRYPOINT. If we want our own args, we can always override CMD at run time.

Bridge Network
==============

A bridge network creates a virtual network inside your system.

How it works:

--> Your VM/container gets its own IP address
--> It connects through a virtual bridge (like a mini router inside your machine)
Traffic goes:
Container → Bridge → Host → Internet

Example:-
=======
In Docker:

Default network = bridge
Containers can talk to each other using internal IPs

Advantages:

--> Isolation (containers are separate from host)
--> Safer (not directly exposed)
--> Multiple containers can communicate internally

Disadvantages:

--> Slightly more complex
--> Requires port mapping (e.g., -p 8080:80)


Host Network:
=============

A host network means the container/VM uses the same network as your computer directly.

How it works:

--> No separate IP
--> Uses the host’s IP address
--> Acts like a normal app running on your system

Example:-
========
In Docker:

--network host

==> App inside container runs directly on your machine’s ports

Advantages:

--> Faster (no network translation)
--> Simpler (no port mapping needed)

Disadvantages:

--> Less secure (no isolation)
--> Port conflicts (can’t run two apps on same port)


Feature			Bridge Network 		Host Network 
=======			==============		============
IP Address		Separate		Same as host
Isolation		High			Low
Performance		Slightly lower		Higher
Port Mapping		Required		Not needed
Use Case		Most apps		High-performance or testing
