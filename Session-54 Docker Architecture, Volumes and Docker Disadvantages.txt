Docker architecture:
====================

1. Docker checks image is available in local or not
2. If available, it will run
3. If not available, it will pull from the docker hub
4. Creates container out of it
5. Send the output to user


Docker client == Docker CLI (Command Line Interface)
==> Docker CLI connects to docker daemon for running
Docker daemon == docker software running


docker run nginx -> Checks whether nginx is available in local
==> If available, creates container out of it and show to client

==> If not available pull from docker hub, store it in local, create container and show to client

*****
Docker architecture contains docker client (build, run, pull) , docker host where docker daemon is running, containers and images and docker registry where docker hub is present.

Whenever we issue a command in docker, daemon checks whether the image is available in local or not. If it is not available, it will pull the image from the docker hub, store it in local, create container and send the response to the user.

==> Docker client/docker command, Docker Host, Docker local registry, Docker central registry or Hub, Docker objects storage, network are part of Docker architecture.

==> When you run docker command, it checks whether image is locally available or not, if not available it will pull from hub, create container out of it and send the response to client.

Docker disadvantages to run images:
===================================

1. You can't rely on single docker host
2. If run multiple hosts, there needs to be some orchestrator
3. Container to container communication is difficult if we run in docker
4. If there is load on application, there should be load balancing --> No Load balancing
5. Autoscaling is not there --> No Autoscaling
6. Network management
7. Where to store secrets?
8. Volumes implementation is not good (If container removes data will be there. If server crashes there won't be any data). If docker host crashes, data will be lost. We can't rely on docker host.


Container Orchestration:
========================

Docker swarm ==>  Native docker orchestrator, Kubernetes, Mesos etc.

==> No autoscaling in Docker swarm, Load balancing is not in our control, networking is poor, no cloud integration.

Kubernetes is an open-source project from google, which overcomes all the disadvantages of running the image in docker.

EKS (AWS) --> Amazon Elastic Kubernetes Service, AKS (Microsoft) --> Azure Kubernetes Service, GKE (Google) --> Google Kubernetes Engine, Openshift (Redhat)


==> We will limit DOCKER for only building the image and KUBERNETES for running the image.
