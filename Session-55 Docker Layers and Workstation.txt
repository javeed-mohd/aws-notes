Databases ==> Stateful

==> Databases ALWAYS store state.
mongodb
redis
mysql
rabbitmq

We can  keep this containers
--> logs (Server logs, container logs.) These are not end user's data.
--> metrics (CPU, Monitoring, Health checks.)

Both are data only but databases are highly crucial data. But, above both are stateful apps only.


1. Don't keep stateful apps in containers, Generally these stateful apps run in VMs. As end user data will be there in database, we prefer not to use containers for stataeful apps.
2. If we want, we can keep not end user stateful apps like logs, metrics.

==> Containers are useful for stateless applications and it is created for stateless apps only.

shell (Single server) vs ansible

==> With in docker host we are using bridge network.


==> Autoscaling, networking, storing secrets, managing volumes is difficult in docker swarm, for heavy applications are not suitable.

We need Kubernetes. We will limit DOCKER for only building the image and use KUBERNETES for running the image.

Docker Layers:
==============

Docker creates intermediate container for every instruction.
It will run next following instruction inside this container -> Create image out of it
Then, it creates another intermediate container from that image, run the next instruction -> Create image out of it

So, for every instruction new layers are created -> Docker exports all these layers into hub while pushing the image
So, for every instruction new layers are created -> Docker exports all these layers into hub while pushing the image

Every instruction, it will create one image and one container.

**** We must keep FREQUENTLY CHANGING INSTRUCTIONS at the BOTTOM of Dockerfile to make the build process fast and storage. Then layer becomes reusable.
