==> apiVersion: apps/v1 is a field you see in a Kubernetes manifest file. It tells Kubernetes which version of the API you are using for a particular resource.

What it means

apiVersion → Specifies the API group + version
apps → The API group (used for workload resources)
v1 → The stable version of that API


kind means the type of resource you want to create.
ex:-  kind: Namespace

==> kubectl api-resources

1. Namespace-level resources:
=============================

NAMESPACED = true → These resources exist within a specific namespace.
Operations on them require the namespace to be specified (or default is used).

Examples:
pods (po) → true
services (svc) → true

2. Cluster-level resources:
===========================

NAMESPACED = false → These resources exist at the cluster level and are not tied to any namespace.
They define cluster-wide behavior or global configuration.

Examples:
nodes (no) → false
persistentvolumes (pv) → false


So whenever you see true, treat it like “namespace-scoped” (VPC-level), and false means “cluster/global-scoped” (Cluster-level or global-level policies).


there are resources categorised based on apiVersion. This makes the maintenance easier, if kept same means when we make some changes in that it will affect all. So, they use different apiVersion.

Labels: (Kubernetes core -> Services, Deployments, can have only 63 characters limitation.)
=======

Labels adds metadata to the resource, Selectors use labels to identify resources inside kubernetes. 

Labels are key-value pairs attached to objects (like Pods, Services, Deployments) to identify, organize, and select them.

***** CrashLoopBackOff -> When container is not able to start
***** ImagePullBackOff/ErrorImagePull -> When your node is not able to pull the image. Image address may be wrong or authentication problems

kubectl describe pod labels ==> For default namespace

kubectl describe pod labels -n roboshop ==> If namespace is roboshop


Annotations: (External tools like Helm, Ingress, Monitoring, can have unlimited characters usage.)
============

Annotations are again like labels adds metadata, but annotations are used to select external resources (Load balancers).
Labels have limitations in key value pairs, length and size. Special characters are not allowed inside labels.

imageregistry: "https://hub.docker.com/"
jenkinsURL: "https://jenkins.joindevops.com/build/job/roboshop/34"

configmap: (configmap)
=========

A ConfigMap in Kubernetes is an object used to store non-sensitive configuration data (Not Confidential) as key–value pair.

A ConfigMap is used to store things like:

Environment variables
Configuration files
Command-line arguments

==> It is not meant for secrets (use a Secret object for sensitive data like passwords or token.

Secrets:
========

Secrets are meant for confidential information.

A Secret is an object used to store sensitive data such as:

Passwords
API keys
Tokens
Certificates

==> A Secret stores data as key–value pairs, similar to ConfigMap, but:

Values are base64-encoded
Kubernetes treats them more securely


******
To get base64 values, we use 
==> echo "admin" | base64

To decode base64 values, we use
==> echo base64value | base64 --decode

Service:
========

A service is a method for exposing a network application that is running on one or more Pods in your cluster.

Service is an object that provides a stable network endpoint to access a group of Pods.

pod1 -> pod2

dns won't work in kubernetes.

If we want pod to pod communication, Ip address of pods are not useful since they are ephemeral. We can use k8s service to achieve,
1. pod to pod communication through Service, service name works as DNS here
2. load balancing

cart -> catalogue

If we have multiple resources, we should always use load balancing to route traffic to desired component.

pod1 -> service -> pod2, pod3, pod4 ==> pod1 connects pod2 through service

Service types:
==============

1. ClusterIP (default)
2. NodePort
3. LoadBalancer
