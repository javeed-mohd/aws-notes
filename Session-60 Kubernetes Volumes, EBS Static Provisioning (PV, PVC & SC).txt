Linux Permissions:
==================

Each permission has a numeric value:

Read (r) = 4
Write (w) = 2
Execute (x) = 1You add the values together for each set of permissions:

How Numbers Are Formed:

7 = 4 + 2 + 1 → rwx (read, write, execute)
6 = 4 + 2 → rw- (read, write)
5 = 4 + 1 → r-x (read, execute)
4 = 4 → r-- (read only)
3 = 2 + 1 → -wx (write, execute)
2 = 2 → -w- (write only)
1 = 1 → --x (execute only)
0 = 0 → --- (no permissions)

Three Groups:
==> Permissions are usually shown as three digits:
[Owner][Group][Others]

Example:

755 → Owner: rwx (7), Group: r-x (5), Others: r-x (5)
644 → Owner: rw- (6), Group: r-- (4), Others: r-- (4)


Ex: chmod 755 file.txt

Means:

Owner can read, write, execute
Others can read and execute only

Access modes in k8 volumes:
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Persistent Volume Access Modes:
===============================

There are four primary access modes supported in Kubernetes: 
ReadWriteOnce (RWO): The volume can be mounted as read-write by a single node. Multiple pods on that same node can still access the volume.
ReadOnlyMany (ROX): The volume can be mounted as read-only by many nodes at the same time.
ReadWriteMany (RWX): The volume can be mounted as read-write by many nodes simultaneously. This is common for shared file systems like EFS.
ReadWriteOncePod (RWOP): A newer mode (stable as of v1.29) that restricts access to exactly one pod in the entire cluster. This ensures no other pod—even on the same node—can mount the volume.


Access Mode               Access Level    Multi-Node
===========               ============    ===========

ReadWriteOnce (RWO)       Read-Write      No
ReadOnlyMany (ROX)        Read-Only       Yes
ReadWriteMany (RWX)       Read-Write      Yes
ReadWriteOncePod (RWOP)   Read-Write      No (One Pod Only)


*******
We can use below access modes for EBS
1. ReadWriteOnce 
2. ReadWriteOncePod -> can mount only a particular pod

Pod is running means it is running in the server.

Reclaim policies: (reclaim policy in k8)
=================

Retain -> Keep the disk and data even after the node is deleted (stateful applications).
Delete -> Delete the disk
Recycle -> Delete the data in disk, but keep the disk.

By default, we have retain as reclaim policy... If we want, we change the policy but obviously that is not required. If we do so, then is no use of volume usage only.
