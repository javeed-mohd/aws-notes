Static provisioning:
====================

PVC (Persistent Volume Claim)	-> Claiming the disk from PV
SC (Storage Class)		-> Part of dynamic provisioning. it creates disk and pv on behalf of us.

EBS vs EFS:
===========

1. EBS is like Hard disk, EFS is like drive following NFS (Network File Sharing) protocol
2. EBS should be in same AZ but EFS can be anywhere in the network
3. EBS is faster than EFS
4. EBS is suitable for Operating System and Databases, EFS is suitable to store some files 
5. EBS is fixed size, EFS can grow automatically (efs size = 50TB) [In project, for os and db we use EBS and for files we use EFS]
6. EBS we can select fs type (ebs fs types in linux), EFS is set to NFS
7. EBS SG is not required, EFS SG is mandatory

Elastic File System (EFS) Dynamic Provisioning:
===============================================

Create Filesystem: EFS (Type EFS in aws search bar - Create EFS, Name - roboshop, vpc - eksctl-roboshop-cluster/VPC)
--> Initially, it will be few bytes and it can grow upto 50TB.

Like EBS, everytime we don't create the File system and we will create a file system named with roboshop and we should give this fs to storage class.
File system is like a folder, in that access points, if we are adding each component for it like application, for application a point will be created (Like a sub-folder). File system can grow upto 50TB. For entire roboshop project, we create a single fs and give that fs id to storage class, then our pvc comes to that fs and creates necessary mount points for each component.
