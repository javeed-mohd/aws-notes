Statefulset -> This is for stateful applications, where data storage is important. like databases.
Deployment  -> This is for stateless applications, where data storage is not required. like backend & frontend components.

In Kubernetes, we won't keep any end-user data (primary data) but we keep logs data, metrics data or any other secondary data.

1. pod names are standard in statefulset mysql-0, mysql-1, mysql-2., etc,  pod names are random in deployment.
2. pods in statefulset are created in order, from 0 to n and deleted in reverse order one by one. pod creation/deletion is random in deployment.
3. pod in statefulset have its own disk. pods in deployment have shared disk.
4. statefulset should have pv, pvc as mandatory. pv, pvc is not required for deployment.
5. statefulset requires headless service to find other nodes in the cluster when data replication is required, deployment does not require headless service.
6. statefulset pods will have same identity. (Even after deletion).

Autoscaling:
============

1. Horizontal scaling
2. Vertical scaling

Vertical scaling:
=================

1GB RAM
8GB HD
2 CPU

--> Stop the server
--> Increase the resources
--> Restart

Disadvantages:
~~~~~~~~~~~~~~
1. Downtime
2. Single point of failure


Horizontal scaling:
===================

You don't increase resources in single server, instead we create replicas.

Advantages:
~~~~~~~~~~~
1. No downtime
2. No single point of failure

taints and tolerations: (taints and toleration in k8s)
=======================

selectors -- > How you control the Pod scheduling to a particular node.

We can assign the labels to the nodes, and ask the scheduler to select the node based on this labels.

taint == paint

If you taint a node, it means kubernetes scheduler will not schedule any pods in that node.


Why to taint:
~~~~~~~~~~~~~

1. We reserve that node to other special workloads.
2. May be, we can attach GPU node to the cluster, we reserve that for AI/ML workloads.
3. DB may accept connections from specific IP, we only send the pods that connects to DB in the tainted node.

****
==> SYNTAX for tainting the specific Pod  ==> kubectl taint nodes node1 key1=value1:NoSchedule


NoSchedule        --> Don't schedule the new pods. (It means before scheduled pods will be running)
PreferNoSchedule  --> Try not to schedule the new pods. Scheduler may schedule the pods. (Soft)
NoExecute         --> Don't schedule new pods and evict existing pods. (Super Hard)
