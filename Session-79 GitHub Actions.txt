GitHub Actions:
===============

Advantages/Pros:
-----------------
1. No need to maintain CI server	[We can run the CI where the code is present whereas in Jenkins we have clone the code, on that we will run the CI server].
We are replacing Jenkins server with GitHub actions so that maintenance can be reduced. 
2. Native support to GitHub		[We have our code in GitHub, integration will become easier when compared to Jenkins]. It will be powerful.


Disadvantages/cons:
-------------------

1. We will not have full control
2. Code must be in GitHub	[If code is not there in GitHub then GitHub actions won't work]
3. Even, we setup GitHub action in GitHub enterprise (self hosted enterprise), it is dependent on internet for actions and marketplace
4. If there is a problem in GitHub side, our pipelines will not work

Heavy dependency, not having full control but there is no problem for maintenanace.

--> Earlier, we were using Jenkins server, now we are migrating to github actions. I can handle both. Even, I have handled migration.		[Making Jenkins setup working as it is in Github actions is known as migration, we are not moving data].

To take outputs from one step to another, we use,
--> In Jenkins - in environment, we will set the variables as empty and set the value in steps. (common way) But, we need to follow  specific syntax to take outputs from one to another in GitHub actions,

- name: Image tag
        id: tag     # id is mandatory, to access the output of this step in later steps.
        run: |
          echo "version=1.0.0" >> $GITHUB_OUTPUT
          echo "image-name=catalogue" >> $GITHUB_OUTPUT

- name: Print previous step output
        run: |
          echo "Version: ${{ steps.tag.outputs.version }}"
          echo "Image name: ${{ steps.tag.outputs.image-name }}"


--> We also have GitHub env which are useful within the job. (search github_env in actions)

- name: github env

          echo "Duration=5 Hours" >> $GITHUB_ENV

- name: Print github env
        run: |

GitHub env works only within the job.

# Job name

If we try to access, we won't get the output.

==> If we want to expose outside of the job, we have to do it through GITHUB_OUTPUT, we have to mention outputs section below runner what all things we want to expose. Then, this can be useful to accessing from other jobs.

github-context:
    runs-on: ubuntu-latest            # Github hosted runners
    outputs:
      image-version: ${{ steps.tag.outputs.version }} 
      image-name: ${{ steps.tag.outputs.image-name }}

deploy:
    needs: github-context             # Depends on above job (github-context) can be accessed using outputs section
    runs-on: ubuntu-latest            # Github hosted runners
    steps:
      - name: Print github env in another job
        run: |
          echo "Image Version: ${{ needs.github-context.outputs.image-version }}"
          echo "Image Name: ${{ needs.github-context.outputs.image-name }}"

This is sequential order of execution.

--> If we want to run the jobs parallelly, we can run them.

Concurrency:	(github actions concurrency search) 
============

name: main-workflow
on: [push]                            # Triggers the workflow on every push to the repository
concurrency:
  group: ${{ github.workflow }}-${{ github.ref_name }}     # main-workflow-main
  cancel-in-progress: true            # If true, present execution will be cancelled, new trigger will happen / If false, until the in progress execution is done, other won't be triggered.

jobs:
  # Job name
  say-hello:
    runs-on: ubuntu-latest            # Github hosted runners
    steps:
      - name: Concurrency build
        run: sleep 60     # The command to execute


We can also keep timeout in concurrency. 
timeout-minutes: 30  # Job will fail if it takes longer than 30 mins.


Conditions:	(search github actions conditions)
===========

Using conditions to control job execution
Prevent a job from running unless your conditions are met.

jobs:
  # Job name
  say-hello:
    runs-on: ubuntu-latest            # Github hosted runners
    steps:
      - name: Main branch
        if: github.ref_name == 'main'
        run: echo "This will be executed, if branch is main"     # The command to execute

      - name: Feature branch
        if: github.ref_name == 'feature-*'
        run: echo "This will be executed, if branch is feature"     # The command to execute
