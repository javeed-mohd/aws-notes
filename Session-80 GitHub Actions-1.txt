GitHub actions:
===============

Pros:
-----
1. No need to maintain CI server	[We can run the CI where the code is present whereas in Jenkins we have clone the code, on that we will run the CI server].
We are replacing Jenkins server with GitHub actions so that maintenance can be reduced. 
2. Native support to GitHub		[We have our code in GitHub, integration will become easier when compared to Jenkins]. It will be powerful.

Pipelines == Workflows

--> We have both Jenkins and GitHub actions, few projects support Jenkins and few are migrating to GitHub actions. Here, we are not migrating the data only process migration. [Data migration is risky, generally databases on-premise to cloud migrating is risky because we need to transfer the actual data. But, here we no need to transfer data, just migrating the process. We will use Jenkins for 1 or 2 PROD Deployments successful and once GitHub actions becomes completely stable then we can deprecate/remove the Jenkins.

On-premise means software or servers are kept and run inside a company’s own building or data center, instead of using them over the internet from a cloud provider.

Pros:
-----
Better control over data
Strong security requirements
Need to work without internet
Compliance/legal reasons

Cons:
-----
Expensive hardware
Needs IT staff
Maintenance and upgrades are manual
