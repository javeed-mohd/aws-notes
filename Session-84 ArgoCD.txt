ArgoCD is an open-source continuous delivery (CD) tool for Kubernetes that follows the GitOps methodology. It automates the deployment and lifecycle management of applications by using a Git repository as the single source of truth.


--> GitOps is a practice where,

Your application's desired state (Kubernetes YAML files, Helm charts, Kustomize configurations, etc.) is stored in Git.
Any change to the application or infrastructure is made through a Git commit.
ArgoCD continuously compares the desired state in Git with the actual state in the Kubernetes cluster.
If they differ, ArgoCD automatically synchronizes the cluster to match Git.

==> How ArgoCD works:

Developer
    |
    | 1. Push changes
    v
Git Repository
    |
    | 2. ArgoCD watches Git
    v
ArgoCD Server
    |
    | 3. Compares desired state with cluster
    v
Kubernetes Cluster


--> GitOps-based deployment – Git is the single source of truth.
--> Automatic synchronization – Deploys changes automatically when Git is updated.
--> Rollback support – Roll back to any previous Git commit.
--> Drift detection – Detects if someone manually changes resources in the cluster.
--> Web UI – View application status, health, and deployment history.
--> CLI and API – Manage applications programmatically.

Supports multiple configuration formats,
Kubernetes YAML
Helm Charts
Kustomize
Jsonnet

Argocd is git ops tool. We are using argocd to manage eks cluster and recently we started deploying few applications with argocd. In argocd, everything is application. It has source, destination and sync policy. When we update source, it will automatically sync that to destination.

We are managing namespaces, storage classes, drivers, load balancer controller, etc., through argocd. application deployments also through argocd. Our CI pipeline updates image versions in helm values file based on environment, our argocd application syncs it automatically.
